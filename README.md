# Telecom ETL Pipeline — SSIS

## Overview

This project implements a telecom ETL pipeline using **SQL Server Integration Services (SSIS)**. It extracts telecom data from source files, applies data cleaning and transformation rules, and loads the processed data into a SQL Server database.

The project is designed to demonstrate practical ETL concepts such as data validation, error handling, auditing, and reliable batch loading.

---

## ETL Architecture

```text
Source Files
     │
     ▼
SSIS Data Flow
     │
     ├── Data Cleaning & Transformation
     ├── Validation
     ├── Error Handling
     └── Audit / Row Tracking
     │
     ▼
SQL Server Database
```

The main SSIS package is:

```text
ETL_Telecom/Telecom_DB.dtsx
```

---

## Key Features

- Extracts telecom data from source files.
- Cleans and transforms incoming records before loading.
- Loads valid records into SQL Server.
- Separates problematic records so errors can be investigated.
- Supports audit-oriented processing and traceability.
- Uses an SSIS project structure that can be opened and executed through Visual Studio / SSDT.

## How to Run

### 1. Clone the repository

```bash
git clone https://github.com/khaledsalah5/ETL_Telecom.git
cd ETL_Telecom
```

### 2. Prepare SQL Server

Restore or recreate the project database using the resources inside:

```text
Other Files/
```

The repository contains both supporting SQL files and a database backup.

### 3. Open the SSIS solution

Open:

```text
ETL_Telecom.sln
```

using Visual Studio with **SQL Server Integration Services Projects / SSDT** installed.

### 4. Configure connections

Update the package connection managers so that they point to:

- the correct local source-file paths;
- your SQL Server instance;
- the required destination database.

### 5. Execute the pipeline

Open:

```text
Telecom_DB.dtsx
```

Validate the package and run it from Visual Studio.

### 6. Validate the results

After execution, verify:

- successfully loaded rows;
- rejected/error records;
- destination table counts;
- audit or processing information generated by the ETL workflow.

## Data Engineering Concepts Demonstrated

### Extract, Transform, Load

The project follows the standard ETL workflow:

1. **Extract** data from telecom source files.
2. **Transform** records through cleaning and validation logic.
3. **Load** valid data into SQL Server.

### Data Quality

Incoming data is processed before reaching the destination so invalid or problematic rows can be identified rather than silently loaded.

### Error Handling

Error handling makes failed records easier to investigate and helps prevent individual bad rows from hiding data-quality problems.

### Auditability

Tracking row processing and ETL outcomes improves observability and makes it easier to validate whether the pipeline completed correctly.

---

## Project Purpose

This repository demonstrates a practical batch ETL implementation using the Microsoft data stack. It covers several responsibilities commonly handled by Data Engineers:

- ingesting data from external sources;
- transforming and validating records;
- loading relational targets;
- handling bad records;
- maintaining traceability across pipeline runs.
